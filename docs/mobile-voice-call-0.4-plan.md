# 0.4 语音通话改版

目标：从聊天页的复选框与录音按钮，改成独立通话页；文字仅作为可展开记录。继续使用已有会话、健康上下文、图片附件与模型配置。

## 流程

1. 聊天页点“语音通话”进入通话页。显示收音、思考、说话、网络错误四种状态；通话页有结束、手动打断/说话、图片和截屏入口。
2. 模型每返回一段稳定句子就交给百炼 Qwen3-TTS-Flash-Realtime，服务器逐包转发 PCM，手机 AudioTrack 边接收边播放。句子按序播放；停止/打断立即丢弃排队音频。模型文字仍完整保存在原会话。
3. 通话期间用 Android AudioRecord 监听讲话。语音活动持续达到门槛，停止正在播放的音频与模型任务，收音直到静默；ASR 返回后沿用现有会话发送。通话中始终保留手动按键以应对噪声或回声。
4. 进入后台、结束通话或权限被拒时释放麦克风与播放器。麦克风仅在可见通话页工作。网络断开保留文字记录并提示重试。

## 边界与验收

- 麦克风由 Android 系统按需授权。优先使用系统回声消除；实际效果由小米 14 的音频路径决定，不能把自动打断的模拟测试当真机验收。
- 流式语音用独立鉴权接口，百炼 Key 不进入 APK/网页。一次最多朗读 2000 字符，服务端句段最多 220 字符，防止排队无限增长。
- 服务端用合成句子核对协议、首包、音频格式、结束事件与中断；前端回归检查通话页、状态、字幕、打断和附件；构建签名一致的 0.4 APK，并验证公网下载。
- 参考：[百炼实时语音合成](https://help.aliyun.com/zh/model-studio/realtime-tts-user-guide)、[客户端事件](https://help.aliyun.com/zh/model-studio/qwen-tts-realtime-client-events)、[服务端事件](https://help.aliyun.com/zh/model-studio/qwen-tts-realtime-server-events)、[Android 回声消除](https://developer.android.com/reference/android/media/audiofx/AcousticEchoCanceler)。

## 实施与验证记录

- 已实现独立通话界面、边接收边播放的 PCM 流、分句合成、收音状态与自动打断。这里使用语音活动检测 → 完整语音片段 ASR → 文本模型 → 流式 TTS，并非模型直接接收实时音频的全双工协议。
- 自动打断阈值是初始值，扬声器回声、蓝牙耳机与噪声环境需在小米 14 上验证；手动按键始终保留。
- 服务端单段最大 220 字符；客户端单轮最多送 2000 字符给语音服务。完整模型文字保留在会话中。
- 已验证服务端鉴权/流式协议单测、Edge 393×852 布局与中断回归、Android release 构建。服务器公网接口通过临时配对设备实测：首个 PCM 包约 0.41 秒，11 包共 165120 字节并正常结束；临时测试设备已撤销。这个数字是短句的服务端合成首包，实际通话还含识别、模型思考和网络延时。
- 小米 14 真机尚未完成本版试用，特别需检查免提回声、说话自动打断、手动按键、后台返回和图片选择流程。
- `QuickModel-0.4.0.apk` 已用与旧版相同的签名构建，versionCode 4；公网下载页、二维码和 APK 哈希均已检查。APK SHA-256：`ba5d558ad0d4c1ca7415cb1a7da41ea3cb0e93c2c7a6e884a2a2436b66883b89`。
